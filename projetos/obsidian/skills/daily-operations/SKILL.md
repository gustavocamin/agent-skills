# Daily Operations Skill

Commands for the operational layer of the vault: what to do today, how to structure
the week, and how to close cleanly without losing what happened.

All commands treat the vault as the source of truth for priorities. Calendar and
external data are inputs; the vault is the output.

**Vault location:** all PARA folders live inside `second-brain/` relative to the
working directory. The root contains only directories — no loose `.md` files.
Each PARA folder may contain subdirectories, so always traverse recursively
(glob `**/*.md`) when reading a folder.

---

## /today

**Generates a grounded daily plan based on recent notes, open projects, and current priorities.**

1. Read:
   - Today's daily note if it exists (Periodic Notes)
   - All `second-brain/01. Projects/` notes — extract `next action` field or last bullet in each
   - `second-brain/00. Inbox/` — flag anything time-sensitive
   - `second-brain/02. Areas/` — scan for responsibilities that need attention today
   - Yesterday's daily note (if available) for unfinished items
2. Identify:
   - Hard commitments: meetings, deadlines, or time-boxed items explicitly dated for today
   - Project actions: one next action per active project, ranked by urgency and energy cost
   - Maintenance: recurring area responsibilities due for attention
   - Optional: one low-stakes item to do if energy allows
3. Build the plan:
   - Separate into Morning / Afternoon / Evening blocks if context suggests a schedule
   - Otherwise: Priorities (max 3) + Supporting tasks (max 5) + Capture queue
   - Flag anything that should be deferred rather than forced into today
4. Output the plan as clean prose or a minimal list. No padding, no motivational framing.
   Close with: "One thing that makes today successful: [single item]"

## /schedule

**Schedules events and work blocks from priorities, commitments, and energy patterns.**

1. Read:
   - `second-brain/01. Projects/` for deadlines and next actions with time estimates
   - `second-brain/02. Areas/` for recurring commitments and maintenance windows
   - Today's and tomorrow's daily notes for existing appointments
   - Any notes that mention energy patterns, peak focus times, or preferred routines
2. Infer energy model from vault context:
   - If notes mention morning focus or deep work preferences, protect morning for cognitively
     demanding tasks
   - If no explicit pattern found, apply default: deep work AM, meetings/calls midday,
     admin/light tasks PM
3. Produce a time-blocked schedule for the requested day (default: today):
   - Each block: time range → task → estimated duration → associated project or area
   - Include buffer blocks between context switches
   - Flag overloaded days explicitly: "This schedule has X hours of work in Y available hours"
4. If asked to schedule across multiple days, distribute tasks by deadline proximity
   and cognitive weight — don't stack all heavy work on one day.

Output: time-blocked list. If a task has no estimate, mark with `[?]` and ask the user
to clarify before committing it to a block.

## /7plan

**Reshapes the next 7 days around what's most "alive" in your thinking right now.**

1. Read:
   - All notes modified in the last 7 days (full vault, excluding Readwise)
   - All `second-brain/01. Projects/` — status, next action, deadline
   - `second-brain/00. Inbox/` — recent captures that signal emerging focus
   - Any Readwise highlights from the last 7 days that sparked annotations
2. Identify what is most "alive": recurring topics, notes edited multiple times,
   Inbox items that keep accumulating around a theme, projects with recent momentum
3. Contrast with what the schedule "should" contain based on deadlines and commitments
4. Propose a 7-day shape:
   - Day-by-day: one primary focus per day + one maintenance commitment
   - Flag conflicts between what's alive and what's due
   - Suggest which projects to defer, which to accelerate, which to timebox
5. Close with: "The week's underlying question: [one sentence that names the real thing
   at stake this week]"

Output: 7 labeled days, each 1–3 lines. Synthesis sentence at the end.
Do not over-specify — leave room for the day to respond to itself.

## /close-day

**Reviews the day, captures lessons, and flags unresolved items for tomorrow.**

1. Read:
   - Today's daily note (if it exists)
   - The plan generated by `/today` (if available in the note or referenced)
   - Any notes created or modified today
   - `second-brain/00. Inbox/` for items added today
2. Reconstruct what happened:
   - What was planned vs. what actually got done
   - What arrived unexpectedly and how it was handled
   - What was deferred and why
3. Extract:
   - **One lesson**: something concrete learned today — about work, a project, or yourself
   - **One loose end**: the most important unresolved item that needs attention tomorrow
   - **One honest note**: something that went unaddressed that you're aware of carrying forward
4. Write a closing entry for today's daily note. Format:

```
## Fechamento

**Feito:** [2–4 bullets of what actually happened]
**Adiado:** [items deferred, with a reason if known]
**Lição:** [one sentence]
**Amanhã começa com:** [one specific action]
```

5. If today's daily note doesn't exist, create it with today's date using the Periodic
   Notes naming convention, add the closing entry, and place it in the correct folder.

## /xdaily

**Pulls X/Twitter posts and threads them into relevant daily notes and vault context.**

1. Accept as input: raw text, a URL, or a pasted thread from X/Twitter.
   If no input is provided, ask: "Cole o texto ou URL do post/thread aqui."
2. Parse the content:
   - Identify individual tweets within a thread (separated by line breaks, numbering,
     or `—` dividers)
   - Extract: author handle, date (if visible), core claim or insight per tweet
3. Classify each post by vault relevance:
   - Which project, area, or resource does it connect to?
   - Is it a standalone insight, a reference, or a prompt for reflection?
4. For each classified item:
   - If it connects to an active project → append to that project's note under
     a `## Referências externas` section
   - If it's a standalone insight → create a capture in `second-brain/00. Inbox/` with frontmatter
     `type: reference` and `source: [handle or URL]`
   - If it connects to a resource topic → append to the relevant resource note
5. For each daily note in scope (today by default):
   - Add a `## X / Twitter` section with the captured items as bullets
   - Format: `- [handle] — [core insight or quote] → [[linked note]]`

Do not copy tweets verbatim into notes without paraphrase unless the exact wording
matters. Prefer extracting the idea over preserving the format.
